vibld 0.6.0: the open-source AI app builder that turns a description into a conventional React and TypeScript project you can read, run and take with you. This release makes pushing to GitHub work on a copy you run yourself, and brings the documentation up to date with everything 0.5.0 added.

This is the code running at [app.vibld.com](https://app.vibld.com), a public beta. See [Status](https://github.com/vibld/vibld#status) for what works and what does not yet.

## GitHub on your own copy

- **Your own GitHub App.** A self-hosted copy now creates and pushes to a GitHub repository for each project through a GitHub App of its own. The builder's install button goes to that App's installation page, which it looks up from GitHub with the App ID and key, so the installation comes back to your copy rather than to app.vibld.com.
- **Docker, Render and a server.** The five `VIBLD_GITHUB_*` settings now reach the builder under Docker, on Render and with `infrastructure/vps`. `.env.example` and `render.yaml` list them.
- **Setup steps.** [Pushing to GitHub](https://github.com/vibld/vibld#pushing-to-github) in the README says how to make the App and where each value goes on Cloudflare, Docker, Render or a server.

## Documentation

- The README, the vibld.com guides, pricing and the roadmap now describe 0.5.0 as it is: the $0.20 Free trial and $1 a month once the account saves a card no other account saved first (or buys a plan or top-up), opt-in auto-reload and Start Build, checkpoint history, the cost shown beside Send, and templates by category.
- The configuration guide lists `VIBLD_FREE_TRIAL_MICRO_USD`, `VIBLD_FREE_DAILY_MICRO_USD` and `VIBLD_FREE_PREVIEW_DAILY_MINUTES`, and says that when your keys cannot serve `VIBLD_MODEL`, a build that does not pick a model is refused rather than run on another one, while a model picked in the builder that your keys serve still runs.

## Known limits

- **Self-hosting is checked by the project, not yet by anyone outside it.** Nobody has deployed to Render or run `cloud-init.yaml` on a real server yet.
- **Under Docker on your own machine**, GitHub cannot reach the webhook, so a merged pull request is not reported back to the builder.
- **Not under Docker:** the nightly cleanup jobs, Stripe and email.
- **The builder's Console and Problems panes** do not show the sandbox's output yet, and say so.
- **Editing an existing repository, and repository search over it, are not built.**
